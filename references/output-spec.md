# 输出规范 (Output Spec v2.1) — 双区块产出与防编造自检

生成前必须加载本文件。**唯一输入是「工作经历档案」JSON**（`references/archive-schema.md`），绝不直接回读杂乱聊天记录，确保所有事实可溯源。

---

## 一、强制防编造四步自检（生成前在脑中跑完，不展示给用户）

1. **数字与事实逐一溯源**：列出草稿中出现的每一个数字、百分比、公司/产品/业务名、工具栈、服务范围；逐项核对在档案 JSON 中的来源字段。**无来源 → 立刻替换为 `【待补充：具体需填项】` 或删除**。
2. **口径与推算诚实标注**：若数字是用户口头推算量级（如「约千级」「月均百单」），保留量级措辞，不篡改成虚假精确数（如「1137」）；百分比若有口径说明，顺手写清。
3. **动词与归属严格匹配**：
   - 用户拍板定方案 → 可用「主导、牵头搭建、从 0 到 1 设计」；
   - 用户主刀落地 → 用「独立搭建、落地、实现、推进」；
   - 用户参与配合 → 用「协同、承接、参与、支持」；
   - 实习/初级岗绝不拔高。
4. **格式与隐私硬检查**：
   - 任职时间严格为 `YYYY.MM–YYYY.MM`（在职写「至今」）；缺起止年月 → `【待补充：起止年月】`。
   - 内部黑话/代号（如未解释的缩写）需在括号提示或建议替换。
   - 若用户要求公司匿名，全文所有区块保持一致，绝不泄露真名。
   - 若填写了 `basic.targetRole`，优先把最贴合目标岗位的 `core` 模块与代表项目排在最前面。

---

## 二、标准输出结构（Markdown，开箱可复制）

### 价值原型（1 句开场点睛）
用 1 句精准的话概括这段经历的职场稀缺定位（依据完全来自档案里的职责组合、工具与结果，禁止空洞鸡汤），例如：
> **你的职场定位**：懂 AI 产品特性的增长型运营中枢——擅长把高门槛模型能力翻译成低摩擦用户增长链路。

### 区块一：工作经历（可直接贴进简历）
- **定位行**：`公司 · 岗位 · YYYY.MM–YYYY.MM`（可附半句最强业务范围或标杆成果）
- **职责 + 传导成果 Bullets（3–5 条）**：
  - **篇幅配比**：`core` 主角模块放前 1–2 条，写满整条价值传导链——**【强动词 + 针对何种痛点/事项 + 方法工具 + 量化成果 + 下游业务价值】**；`routine` 日常模块精炼成 1 句干脆的「动作 + 范围/交付」，不注水。
  - 优先嵌入 `metricsLibrary` 中已核实的数字；关键缺口保留 `【待补充：XX】`。
  - **禁用空心水词**：`负责相关工作`、`积极参与`、`锻炼了能力`、`取得了良好效果`、`大幅提升`（无依据时）。

### 区块二：代表性项目经历（每个项目独立成节，绝不合并）
每个项目按以下高密度格式输出：
- **项目标题**：`项目名 ｜ 个人角色定位（如：独立主导 / 核心主刀）`
- **一句话摘要**：针对什么业务卡点，用什么核心策略拿到了什么结果。
- **结构化 STAR（连贯可读，非机械填空感）**：
  - **背景与卡点**：当时面临什么约束或痛点（`S + hard`）。
  - **方案与权衡**：为什么选这个解法、个人主导了哪几步关键动作与工具链路（`T + decision + A + own`）。
  - **结果与沉淀**：可衡量的业务结果 + 沉淀下的可复用资产（`R + asset`）。

### 辅助件一：量化成果库（数字弹药总览）
把 `metricsLibrary` 整理成一行清晰标签（含来源口径），让用户一眼看清自己手握多少真材实料：
> `300+ 场景模板` · `首日出片率 22% → 41%` · `会员首充 +6.5pp` · `投稿 1.2万+ 件` · `自然曝光 8000万+`

### 辅助件二：缺口诊断清单（≤ 5 条，按简历提分价值排序）
每条写清 **缺什么 (`what`) → 怎么补 (`todo`) → 去哪找 (`where`)**，降低用户补数的心理门槛。

### 辅助件三：面试防御指南（≤ 3 条，框定为“提前护航”）
针对简历里最亮眼、最容易被面试官深挖的点，给出 **高概率追问 (`q`) + 提前怎么答才稳 (`prepare`)**——特别覆盖口径分母、方案权衡、团队 vs 个人边界、AI/工具实际掌握深度。

## 三、生成后的一轮精修协议

出稿后，用一句自然的话邀请微调：
> 「初稿落地了。哪一条你想换个侧重点，或者刚想起一个具体数字 / 想对标某个目标岗位 JD？直接告诉我，我只改对应部分、帮你原地升级。」

用户补充新事实后：**更新档案 JSON → 重跑防编造自检 → 仅重生成受影响的条目与成果库/缺口清单**。
