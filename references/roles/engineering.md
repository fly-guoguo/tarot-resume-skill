# 岗位族：研发 / 算法 / 数据工程 (Engineering)

Covers：后端、前端、客户端、全栈、算法/大模型、数据工程/数仓、测试/测开、运维/SRE、架构师、Tech Lead、研发实习。
> **管理向切换**：若用户重心在带团队、定技术路线与跨团队协调，量化维度增加「团队规模、核心系统 SLA、研发效能提升、技术评审拍板权」。

## 1. Q1 常见模块分流（Core vs Routine）
- **高含金量主角盘（优先深挖）**：高并发/核心链路架构演进、瓶颈排查与性能/成本大降、从 0 到 1 核心平台/AI Agent 基建搭建、高风险系统重构与零故障迁移。
- **常规盘（精炼 1 行）**：日常 CRUD 需求迭代、常规 Bug 修复、例行发版与值班。

## 2. Q2 量化维度弹药库 + 倒推公式

| 维度 | 编号量级选项 | 没统计过时怎么倒推 |
|---|---|---|
| 性能（RT / P99 / QPS） | ①降 30%+ ②快 2–5 倍 ③数量级提升 | 抓优化前后的慢查询日志 / 监控均值，或压测峰值对比 |
| 稳定性（可用性 / 故障） | ①P1/P2 事故清零 ②故障率降半 ③99.95%+ | 以前每月/每季线上告警或回滚几次 vs 治理后几次 |
| 流量与数据规模 | ①千级 QPS ②万级 QPS ③日千万/亿级数据 | 看监控大盘日均请求量、峰值并发、单表数据量或日增行数 |
| 研发/交付提效 | ①省小时/次 ②发布提速 50%+ ③替代人工值守 | 原来发一次版/跑一次回归要几小时 × 每周频次 |
| 成本节省（算力/存储） | ①月省数千 ②月省数万 ③年省几十万+ | 下线/缩容的机器核数、GPU 卡数或云账单差额 |
| 算法/质量指标 | ①准确率/召回率 +X% ②Badcase 降 X% ③线上转化 +X% | 离线评测集指标 + 线上 A/B 指标分开写清 |

## 3. 反差痛点 & 下游传导话术
- **反差开路**：「在你动这刀重构/优化之前，老系统最让人抓狂的瓶颈是什么？大促必炸、接口卡到超时、还是每次改需求都牵一发动全身？」
- **下游传导**：「性能提上来 / 工具搭好之后，直接惠及了谁？是让上游业务方敢接大促流量了、帮多少位研发同学每天少踩坑，还是把云成本账单实打实压下来了？」

## 4. Q3 高段位方案权衡（Decision）追问
- **技术选型 Trade-off**：面对一致性 vs 吞吐、开发周期 vs 扩展性、自研 vs 开源选型，**当时放弃了哪几个备选方案？为什么现在这个方案在当时约束下是最优解？**
- **极端边界与兜底**：怎么保证灰度迁移不丢数据？降级、熔断或回滚方案是怎么设计的？
- **个人拍板边界**：这套架构是你画图拍板，还是架构师定方案你负责关键模块编码实现？

## 5. 输出强动词与黄金范例
- **强动词**：架构设计、主导重构、定位根因、抽象沉淀、性能优化、灰度迁移、降本治理、独立交付。
- **范例**：「针对大促期间订单查询接口 P99 飙升至 800ms 的瓶颈，主导重构查询链路并引入分层缓存与覆盖索引，将 P99 降至 120ms、DB 负载下降 65%，平稳支撑日均 300 万次调用零故障。」

## 6. 面试防御杀招（防翻车）
- **压测流量 ≠ 线上真实流量**：务必区分单机压测 QPS 与线上峰值 QPS，绝不混写。
- **无基线百分比**：只写“性能提升 50%”不写从多少降到多少，面试官会直接怀疑水份。
- **团队系统归属**：区分“独立设计并编码核心链路” vs “参与其中某一微服务模块开发”，碰过一两天的模块绝不写主导。
- **AI/LLM 项目深挖**：必被问幻觉治理、评测集怎么建、Prompt/RAG 调优前后的量化对比、延迟与 Token 成本控制。
